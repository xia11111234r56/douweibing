# 豆卫兵技术总结（国创赛口径）

> 用途：国创赛 PPT「核心技术」页、BP「技术方案」章节、答辩话术的一手材料。
> 纪律：**每一条指标均可追溯到 ml/experiments/*.json 或代码**；任何不可复现 / 夸大数据一律不写（见文末「禁用清单」）。
> 数据口径：识别准确率一律以 **5 折 CV 0.8519±0.022** 为准；严重度 **0.844**；多模态增益 **+0.0112**。

## 0. 一句话技术定位

> **面向绿豆生产场景的「拍照识别 → 严重度分级 → 环境融合 → 知识图谱 + 防治方案 → 风险区划」全链路智能病害防控系统**，端侧小程序薄端采集，云端 ONNX 模型 + 规则知识引擎推理，Web 平台做数据可视化管理。

技术关键词（可用于报名概述/BP 摘要）：
图像分类（MobileNetV3 迁移学习）· 严重度分级深度模型 · 多模态环境融合 · 动态知识图谱 · 图推理引擎（防治路径+可解释链） · 病害风险区划规则模型 · ONNX 端侧推理 · 防治方案知识库

## 2. 技术模块清单

### M1 图像分类识别（病害识别主模型）

| 项 | 内容 |
|---|---|
| 模型 | MobileNetV3-Large（torchvision 预训练）+ 分类头替换 |
| 分类体系 | **10 类**：健康/晕疫病/炭疽叶斑病/轮纹叶斑病/枯萎病/病毒病/细菌性疫病/叶腐病/细菌性萎蔫/虫食 |
| 训练 | 两阶段迁移：① 公开数据（PlantVillage/Mendeley）预训练 → ② 自采绿豆数据微调（40 epoch, AdamW lr=1e-4, 余弦退火）；强数据增强（RandomResizedCrop/翻转/旋转/ColorJitter） |
| 预处理 | 两段缩放 256→224（BILINEAR）+ ImageNet 归一化，与评估协议严格一致 |
| 部署 | ONNX Runtime CPU 推理（`classifier.onnx` ~轻量级），输入 [1,3,224,224] |
| **真实指标** | **5 折交叉验证 0.8519±0.0223**（601 张真实图全量，每张恰评估一次；含主要病害逐类召回） |
| 主要类召回 | 炭疽叶斑病 0.929、晕疫病 0.846、健康 0.818、病毒病 0.738、细菌性萎蔫 0.70 |
| 代码 | `ml/train_classifier.py`、`ml/finetune_cv.py`、`ml/export_onnx.py`、`backend/app/services/model_inference.py` |

**国创赛话术**：自建 601 张真实绿豆叶片图像库、10 类分类体系，迁移学习 + 5 折交叉验证评估，识别一致率达 **0.8519**，模型导出 ONNX 可在普通服务器 CPU 实时推理。

### M2 严重度分级（轻/中/重）

| 项 | 内容 |
|---|---|
| 方案 | 冻结骨干（绿豆 10 类微调后的 MobileNetV3 features，eval 模式，448×448 输入）提取 960 维特征 → sklearn 逻辑回归 3 分类 |
| 分级标准 | 轻/中/重 三档，阈值参考刘学敏等《大豆灰斑病分级标准》合并方案 |
| 数据 | 179 张人工图级标注（轻/中/重三组） |
| **真实指标** | **5 折 CV 一致率 0.844±0.051**；轻/中/重召回 0.915/0.800/0.819 |
| 兜底方案 | 面积比法（颜色形态学，一致率仅 0.32）与 MobileSAM 面积比在主视图级标注上无法对齐，仅作深度模型缺失时回退 |
| 代码 | `ml/train_severity.py`、`ml/export_severity_onnx.py`、`backend/app/services/severity_model.py` |

**国创赛话术**：面积比等传统方法在小样本图级标注上失败后，改用「深度特征 + 逻辑回归」方案，稳定实现轻/中/重三档分级，5 折 CV 0.844 —— 分级结果联动差异化防治方案。

### M3 多模态环境融合（图像 + 环境上下文）

| 模态 | 来源 |
|---|---|
| 图像 | 拍照叶片（主模态） |
| 拍摄环境 | 照片 EXIF 自动提取拍摄月份、GPS 经纬度 |
| 气候 | WorldClim 2.1 公开气候栅格（全国格点下采样 CSV），按 GPS 最近邻回查当月均温/降水 |
| 用户输入 | 生育期（苗期→成熟期）/ 天气档位（高温高湿/阴雨连绵/雨后天晴/晴热干旱/虫害盛发）/ 种植方式（露地/大棚） |

**融合方式**：知识规则后验修正——天气/温度规则对候选病害置信度做 ±修正后再排序（如「高温高湿」上调叶斑病/锈病/炭疽病 +0.04、「低温」上调锈病 +0.02、均温≥25℃ 上调叶斑/炭疽/细菌性疫病 +0.02）。

**真实实验证据**（`ml/experiments/multimodal_ablation.json`，复用生产 ONNX + 后端规则代码，89 张测试图）：
- 无环境基线：0.8315
- 加「天气:高温高湿」：**0.8427（+0.0112）**，1 例错判翻案为正确（炭疽叶斑病 误判→修正正确）
- EXIF+WorldClim 自动模态单独作用时与基线持平（规则主要在天气档明确时触发）

> 诚实口径：环境模态增益有限且依赖用户天气输入质量；PPT 写「环境上下文提升识别鲁棒性」可，勿夸大数值。

代码：`backend/app/services/env.py`、`backend/app/services/knowledge_rules.py`、`ml/ablation_multimodal.py`

### M4 动态知识图谱（病害知识语义网 + 图推理引擎）

| 项 | 内容 |
|---|---|
| 数据模型 | 三元组表 `graph_nodes` + `graph_edges` 为**唯一事实源**（label：寄主/病害/症状/药剂/环境；relation：感染/表现为/防治/适宜/易混淆，带权重） |
| 双后端图引擎 | **自研图引擎抽象层**（services/graph_backend*.py）：SQL + networkx 生产默认（零额外依赖）；**Neo4j 真图数据库本地演示/验证**，跑原生 Cypher（shortestPath 多跳图算法）；Neo4j 缺失/故障**自动回落 SQL**，`GET /api/graph/engine` 透明暴露引擎状态 |
| 图算法 | 防治路径推荐 `GET /api/graph/path`（任意节点最短路径 / 病害→防治路径）；可解释推理链 `GET /api/graph/reason`（寄主→感染→病害→症状→环境→防治 **5 段链**，每步带权重与依据） |
| 动态性 | **识别热度回写**病害节点 `properties.heat`（Web 图谱按 heat 缩放节点大小，随使用肉眼可见）；**用户纠错自动沉淀「易混淆」边**（weight 累计次数）；管理员运行时增改节点/边 |
| 一致性 | SQL 表为事实源，Neo4j 只读只算 + 尽力镜像（写先落 SQL 再镜像），漂移由 `data/sync_neo4j.py` 全量重建自愈（db_id 为键幂等可重跑） |
| 代码 | `backend/app/services/graph_backend*.py`、`graph_reason.py`、`routers/graph.py`、`data/sync_neo4j.py`、`data/seed.py` |

**国创赛话术**：病害知识以「节点-关系-权重」语义网存储并支持运行时动态扩展；自研双后端图引擎抽象层——生产用 SQL 三元组表保证稳定可用，本地 Neo4j 真图数据库验证 Cypher 图算法；图推理引擎把「查到病害」升级为「**算出防治路径与推理依据**」。

**一句话要点（报名/PPT 可直接用）**：
1. 自研双后端图引擎抽象层——SQL 三元组保证生产可用，Neo4j 真图数据库验证图算法与 Cypher；
2. 图推理引擎：病害→症状→环境→防治 5 段可解释推理链，每步带权重与依据，从「查到」升级为「算到」；
3. 动态知识图谱：识别热度回写节点、用户纠错自动沉淀「易混淆」边，图谱随使用生长。

### M5 防治方案引擎（分级精准防治）

- 知识库结构：`diseases × severity_level × method_type`（化学/农业/生物/注意事项）→ `treatments` 表
- 识别链路：病害 top1 + 严重度 → 按严重度档位取对应防治方案，随识别结果一并返回
- 另有 `pesticide` 药剂库 + 病害-药剂多对多，支持「该用什么药」查询

**国创赛话术**：不是只给「是什么病」，而是给出「这个严重度下该怎么做」的分级方案，贴近农户实操。

代码：`backend/app/models/disease.py`、`backend/app/services/recognize.py`

### M6 GIS 病害风险区划（区域预警）

| 项 | 内容 |
|---|---|
| 风险模型 | 规则式适宜度指数（0-100）= 100×(0.5×温度适宜度 + 0.5×湿度适宜度)；6-8 月（绿豆开花结荚关键期）均温与累计降水 |
| 数据 | WorldClim 2.1 气候栅格 → 省级聚合；产量数据为 FAOSTAT/OWID **干豆口径**（如实标注，非纯绿豆） |
| 等级 | 4 档：低(<40)/中(40-60)/较高(60-75)/高(≥75) |
| 呈现 | ECharts 中国地图 choropleth + 省份点击详情卡（指数/等级/6-8 月温湿）+ 全球干豆产量分布（2019-2024，年份切换，吨为单位） |
| 代码 | `backend/app/services/risk_model.py`、`backend/app/routers/gis.py`、`web/src/views/Gis.vue` |

**国创赛话术**：基于公开气候大数据构建区域性病害风险区划，指导不同省份差异化用药与监测优先级。

## 3. 技术演进路线（研发历程，可用于 PPT「研发历程」页）

1. 公开数据预训练（PlantVillage/Mendeley）→ 验证迁移学习可行
2. 自采绿豆数据整理为 10 类训练/验证/测试集
3. 两阶段微调 + 强数据增强，首次达标评估（固定测试集 0.8315）
4. 发现固定测试集不可复现问题 → 多种子复现实验（4 seed 0.823±0.027）→ 改用 5 折 CV 统计口径（0.8519±0.0223）✅
5. 严重度方案迭代：面积比 0.32 → MobileSAM → 深度特征 + LR **0.844**
6. 多模态环境融合消融验证（+0.0112）
7. ONNX 导出 + 生产 CPU 推理 → Web/小程序部署上线
8. 动态知识图谱 + GIS 风险区划 + 风险规则模型升级（climate-rule-v2）
9. 图谱升级双后端图引擎：Neo4j 真图数据库落地 + 防治路径推荐 + 5 段可解释推理链 + 动态回写（heat 热度 / 易混淆边）
