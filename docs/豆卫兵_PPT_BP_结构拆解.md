> **数据纪律**：所有标注【待补】的位置都是要你填**真实数据**的地方，来源必须写清楚（官网 / 文献 / 调研 / 实验室自测），**绝不编造**。

## 一、答辩 PPT 一页页怎么写（16 页版）

> 每页：**页标题 / 讲什么 / 视觉 / 对应维度**。计算机设计大赛 10 分钟版可直接用；若压缩到 5 分钟，砍 P6、P9 详情、P16 后半。

### P1 封面
- **标题**：豆卫兵——绿豆病害智能识别与分级防治一体化平台
- **副标**：AI 影像识别 × 环境多模态 × 病害风险区划；「计算机设计大赛 · 智慧农业应用」
- **视觉**：LOGO + 一张识别界面截图背景，浅绿主色
- **维度**：第一印象

### P2 痛点真（背景：为什么做）
- **讲什么**：绿豆是我国重要食用豆类作物，病害是减产主因之一；基层痛点=**病害识别难**——农技人员短缺、早期症状肉眼易混淆、误诊延误防治窗口。
- **证据**：① 权威文献/统计（绿豆产量、病害损失占比）【待补：查中国农业农村部、FAOSTAT、相关论文，注明出处】；② 你的调研（走访农户/农技站/专家访谈，附照片记录）【待补：需真实访谈记录】。
- **维度**：真（痛点真，有数据支撑）

### P3 痛点深（根因剖析）
- **讲什么**：不是「农户笨」，是现有手段够不着——人工识别依赖经验、植物医生 APP 多为通用作物、识别结果不给防治方案。把痛点拆成三层：**识别难 / 分级难 / 防治指导缺位**。
- **视觉**：痛点鱼骨图或「现状 vs 应有」对照。
- **维度**：深（穿透表象、量化普遍性）

### P4 市场准+大（空间）
- **讲什么**：目标客户精准画像——**绿豆种植户 / 农技站 / 基层植保服务点**；这是刚需还是弱需求，用需求弹性角度自问。
- **证据**：【待补】绿豆种植面积、农户数量、农业数字化渗透率——**必须真实数据**（农业农村部统计公报、行业报告、FAOSTAT），来源写在角标。
- **维度**：准（精准）+ 大（容量）

### P5 方案总览（产品怎么闭环）
- **讲什么**：三层结构——**微信小程序（用户端：拍照识别→分级→防治建议，薄端本地存储）→ 识别 API（ONNX 推理）→ Web 管理平台（GIS 风险区划、天气 5 档联动、数据看板）**。
- **视觉**：一张架构图，一屏装下。
- **维度**：真（已上线，不是纸面）

### P6 新·技术一（识别模型）
- **讲什么**：MobileNetV3 骨干 + 迁移学习，10 类病害；**5 折 CV 0.8519±0.022**（说明是交叉验证、非回代）；配训练曲线/混淆矩阵/部分识别截图。
- **难点必讲**：样本只有 601 张 → 迁移学习 + 数据增强解决小样本；类间相似（叶斑类病害易混）。
- **维度**：新 + 深

### P7 新·技术二（环境多模态）
- **讲什么**：病害发生与温湿度强相关 → 识别时并入天气/温湿环境模态，**消融实验 +0.0112**（0.8315→0.8427）。
- **难点**：环境数据如何对齐到识别样本、WorldClim 长期气候均值 vs 实时天气的口径差异。
- **维度**：新（差异化，通用 APP 没有）

### P8 新·技术三（严重度分级）
- **讲什么**：不止「什么病」，还分「重不重」——mobilenetv3 + LR 分级，**5 折 CV 0.844**；分级直接决定防治建议力度。
- **难点**：分级边界主观性强 → 标注口径统一、面积比对照失败做了对照组【如实讲清】。
- **维度**：新（比「识别」多一层价值）

### P9 新·技术四（工程落地）
- **讲什么**：ONNX 导出部署、推理延迟、小程序端**本地存储**（隐私友好）、生产环境 112.126.78.207 真实可访问。
- **维度**：新（模式新：薄端 + 识别服务化）

### P10 深·技术难点总结页（可选，评委深挖页）
- **讲什么**：每个技术点按四问浓缩成一张表——**是什么 / 原理 / 难点 / 落地 / 效果**。评委大概率从这里追问，准备好每格的 1 分钟展开。
- **维度**：深（为什么别人做不出 / 为什么我们更优）

### P11 强·定量竞品对比
- **讲什么**：**定量**对比表，维度：识别作物、是否多模态（环境）、严重度分级、风险区划、离线/本地存储、部署形态。
- **证据**：【待补】竞品（如 Plantix、识农、各种植物识别 APP）按官网/实测填真实数字，**不要用「更强、更好」定性词**。
- **维度**：强

### P12 强·商业模式（钱到钱的闭环）
- **讲什么**：**目标客户 → 怎么获客 → 怎么收费 → 钱从哪来**。建议：C 端基础识别免费（获客）→ B 端农技站/合作社增值服务收费（区划报告、批量诊断）；服务产品化，避免「卖时间」天花板。
- **注意**：这一页对计算机设计大赛是加分非必需；冲创新大赛则必备。
- **维度**：强

### P13 强·团队
- **讲什么**：成员分工（模型 / 前端小程序 / 后端平台 / 数据标注）、互补性、指导老师。若申报创业赛道：股权/分工说明。
- **维度**：强（投人）

### P14 成果与佐证
- **讲什么**：论文投稿、《智慧农业（中英文）》、生产部署截图、测试报告（自己测 + 第三方【待补】）、演示录屏二维码（可现场扫码打开）。
- **维度**：真（成果真，可查证）

### P15 红·社会价值
- **讲什么**：乡村振兴 × 智慧农业 × 粮食安全 × 农业科普；小程序里的综合科普页正好讲「红」。一张图：AI 下沉到田间地头。
- **维度**：红

### P16 展望 + 结束
- **讲什么**：数据集扩到更多豆类/作物、端侧推理离线可用、对接更多基层农技站试点【如实】。一句话收尾 + 联系方式。
- **维度**：成长性

## 二、BP 章节怎么写（商业计划书，冲创新大赛才需完整写）

> BP 是「证据底座」，被网评细读的概率最高，**每一个数字都要能追溯**。

1. **执行摘要**：一页讲完——痛点、方案、技术壁垒、市场、团队、融资金额（如适用）。写完其余章节再回写它。
2. **市场痛点与机会**：复用 P2/P3/P4 内容 + 完整调研附录（问卷、访谈纪要）。
3. **解决方案**：产品三层架构 + 每个模块的真实功能截图。
4. **技术壁垒**：5 折 CV、消融、分级、ONNX 部署——全部「原理→难点→落地→效果」，配论文/实验记录佐证。
5. **市场分析**：【待补真实数据】TAM/SAM/SOM 或「容量≈种植面积×农户数×服务单价」的推算链，每一步来源标注。
6. **商业模式**：P12 展开：定价、获客渠道（农技站推广/学术会议/朋友圈）、单位经济模型。
7. **竞争分析**：P11 表格 + 3-5 家竞品详细档案（真实）。
8. **营销推广**：细分领域（农业）走行业渠道；线上做内容科普引流。
9. **团队**：简历 + 分工 + 价值观。
10. **财务与融资**：收入预测（如实标注假设）、成本、资金用途。
11. **风险与合规**：数据真实、知识产权、技术迭代、竞争风险 + 应对。
12. **佐证材料附录**：论文/软著/测试/部署/调研记录。

## 四、答辩讲稿衔接话术（真深新红 × 准大强 串成一条线）

- **开场（30s）**：「我国绿豆……病害一年损失……（真实数据）。但农户目前识别病害，要么靠经验、要么靠通用 APP——既不认识绿豆的病害，也不会告诉他重不重、怎么防。」
- **转方案（15s）**：「所以我们做了豆卫兵：小程序拍照→识别→分级→防治建议，后台还有一张基于温湿度的全国绿豆病害风险地图。」
- **技术（60s）**：「识别模型 5 折交叉验证 0.8519，加了环境多模态还能再提 1.1 个点；严重度分级 0.844；全部 ONNX 部署，现在线上就能用。」
- **收尾（15s）**：「我们不是做了一个 demo，是做了一个已经在跑的系统——论文已投、平台已上线、识别已可用。下一步把它送进更多乡镇。」
