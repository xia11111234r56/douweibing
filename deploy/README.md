# 豆卫兵 · 上线部署指南

把「豆卫兵」小程序从本地开发态（`127.0.0.1:8000`）发布成线上可用的小程序。适用对象：**个人主体小程序账号**、有云服务器 + 域名预算。

---

## 0. 总体架构与成本

```
微信小程序（原生，已就绪）
   │   HTTPS
   ▼
云服务器（Ubuntu 24.04，大陆节点）
  ┌────────────────────────────────────┐
  │ Nginx（HTTPS 终结 + 反代）          │
  │   └── uvicorn :8000（FastAPI）     │
  │         ├─ ONNX 分类（MobileNetV3） │
  │         ├─ 严重度分级（深度模型）    │
  │         ├─ 知识规则 / 环境模态      │
  │         └─ MySQL（识别记录/知识库） │
  └────────────────────────────────────┘
```

| 项目 | 推荐 | 预算 |
|---|---|---|
| 云服务器 | 腾讯云/阿里云**轻量 2核4G**，大陆节点，Ubuntu 22.04/24.04 | 约 60-80 元/月（年付更省，约 700-900 元/年） |
| 域名 | `.cn`（约 30-40 元/年）或 `.com`（约 60-70 元/年） | 40-70 元/年 |
| HTTPS 证书 | Let's Encrypt 免费 DV 证书 | 0 元 |
| **合计** | | **约 800-1000 元/年** |

> 内存选 4G 的原因：MobileSAM 严重度推理 + 分类模型在 2 核上够跑，但 2G 会非常吃紧。

**时间线**：备案（1-3 周，大陆节点必须）是唯一的硬等待。备案期间可以并行做：服务器初始化、小程序 UI 打磨、提审材料、模型优化。

## 1. 采购与备案

### 1.1 购买域名
- 在腾讯云/阿里云/华为云任选，注册一个域名。
- 选一个短好记的子域，如 `api.douweibing.cn`（API 单独用一个子域名，方便以后加 Web 平台）。
- 域名需**实名认证**（身份证）。

### 1.2 购买服务器
- 轻量应用服务器，大陆节点，2核4G，Ubuntu 24.04。
- 服务器所属账号与域名同账号最省事（备案好做）。

### 1.3 ICP 备案（关键，个人主体可做）
- 个人备案只需要：身份证 + 人脸核验 + 手机号，**不需要营业执照**。
- 服务商控制台里「备案」入口按流程填，全程免费，1-3 周下号。
- **备案主体要与小程序主体一致**（都是你个人），最稳妥。
- 备案通过前，域名不能对外提供 web 服务（80/443 被监管）。但可以用「服务器 IP + 端口」开发联调。

### 1.4 微信小程序账号确认
- 现有 appid 为个人主体（具体值不写入公开仓库，导入小程序时填自己的 AppID）。
- 植物病害识别属于**工具类目**，个人可发布；但文案**不能出现"诊断/医疗/治疗"**这类词，统一叫「**识别 / 参考 / 防治建议**」，否则会被要求医疗类目（需企业资质）。

## 2. 本地准备：要上传什么到服务器

| 内容 | 路径 | 说明 |
|---|---|---|
| 后端代码 | `backend/`（**排除 `.venv`**） | 上传到 `/opt/dc2/backend` |
| 模型文件 | `backend/models/classifier.onnx` + `labels.json` | 必须带上，否则识别返回 503 |
| 生产配置 | `backend/.env`（用 `deploy/.env.production.example` 改） | 服务器上生成，**不要提交仓库** |
| 部署脚本 | `deploy/` | 上传到 `/opt/dc2/deploy` |
| 空间数据（可选） | `data/spatial/worldclim_china.csv` | 不传也能跑，环境回查自动降级 |

传输方式：本机装个 `scp` / `rsync`，或直接用服务商控制台的「文件管理」上传压缩包后解压。

## 3. 服务器初始化

```bash
# 1. 上传代码后，进入 deploy 目录
sudo bash provision.sh api.douweibing.cn

# 2. 修改数据库密码（init_mysql.sql 里的 CHANGE_ME_DB_PASSWORD）
sudo mysql < /opt/dc2/deploy/init_mysql.sql   # 已在脚本内执行

# 3. 检查后端是否起来
systemctl status dc2-api
curl -fsS http://127.0.0.1:8000/api/health
```

`provision.sh` 会完成：装系统包 → 建用户 → 建 venv 装依赖 → 启动 MySQL → 配 nginx → 注册 systemd 服务 → 本机探活。

**注意**：证书未签发前脚本会用临时自签证书占位，让 nginx 先能起。备案通过后执行正式签发：

```bash
sudo certbot --nginx -d api.douweibing.cn --agree-tos --no-eff-email -m you@example.com --redirect
```

### 数据库
- 推荐 MySQL（与项目文档一致）：表结构由后端启动时 `create_all` 自动建，无需手动迁移。
- 想先跑通也可以改用 SQLite，`.env` 里换一行 `DATABASE_URL` 即可。

### `.env` 必须改的
- `JWT_SECRET`：服务器上 `openssl rand -hex 32` 生成，别用默认值。
- `DATABASE_URL`：填 `init_mysql.sql` 里设的密码。

## 4. 小程序侧上线配置

### 4.1 改 API 地址
`miniapp/app.js` 第 8 行：

```js
API_BASE_URL: 'https://api.douweibing.cn',   // 原来是 http://127.0.0.1:8000
```

### 4.2 微信公众平台后台（mp.weixin.qq.com）
1. **开发管理 → 开发设置 → 服务器域名**：
   - `request 合法域名`：填 `https://api.douweibing.cn`
   - 必须 HTTPS 且已完成备案。
2. **设置 → 服务内容声明 → 用户隐私保护指引**：
   - 声明收集：相机权限、相册（上传图片识别）、识别记录（本地存储）。
   - 用途：拍摄/选择绿豆叶片照片，进行病害识别与防治建议。
3. **设置 → 基本设置 → 类目**：选「工具」相关类目。

### 4.3 提审
- 上传代码 → 提交审核 → 审核通过 → 发布。
- 审核一般 1-7 天，被驳回会注明原因，按提示改。

### 4.4 发布前文案自查
- 页面上"诊断/确诊/治疗"等词改为「识别/参考/建议」。当前小程序已去 AI 腔，提审前再扫一遍。
- 结果页低置信度要有「仅供参考」类提示（建议加，下面 6.4 提）。

## 6. 常见问题

**Q：识别返回 503「模型未就绪」**
`models/classifier.onnx` 没传上去，或 `MODEL_DIR` 路径不对。

**Q：严重度分级慢，识别超时**
- 在线接口走深度严重度模型（mobilenetv3 骨干 + 逻辑回归），单张毫秒级；若该模型缺失会回退到颜色形态学面积比，二者都不可用才会变慢或失败。先实测单张耗时：`curl -X POST .../api/recognize` 计时。
- 超过 25 秒：小程序端 `api.js` 超时已放宽到 60s；还超就降级方案——**识别接口改为先返回分类结果，严重度异步返回**。
- nginx `proxy_read_timeout 90s` 已放长，别调更大（用户等不住）。

**Q：图片太大被拒（413）**
`client_max_body_size 20m` 已配。小程序端仍建议上传前用 `wx.compressImage` 压到 1MB 以内再转 base64，省流量也省推理时间。

**Q：审核被驳回「涉及医疗/诊断」**
改文案，去掉诊断类词汇，明确"病虫害识别参考工具"。

**Q：备案还没下来，想先让队友真机用**
微信开发者工具「详情 → 本地设置 → 勾选不校验合法域名」，`API_BASE_URL` 临时指向电脑局域网 IP（`http://192.168.x.x:8000`），手机与电脑同一 Wi-Fi 即可预览。这只能用于体验版/开发版联调，发布必须走 HTTPS 域名。

## 7. 演示/答辩时的部署加成

- 线上域名 + 真机识别，答辩时直接打开小程序给评委看，比录屏有说服力。
- `deploy/` 这份部署文档本身就是"系统化、可运维"的证据，可放进结题材料。
- 上线后去田间真拍一批照片走真实流程，把识别结果、耗时、误判案例记下来——这就是评委要的"实用价值"实据。
